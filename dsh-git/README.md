# @local/dsh-git

在 DSH 右侧栏里用可视化方式操作 Git，参照 VS Code 的源代码管理面板。

## 它长什么样

右侧栏的「+」引导卡片列表里，**Git** 排在「浏览器」下面。点一下就开一个 Git tab，
可以多开、可以拖到分屏、可以浮动——和浏览器、文档预览是同一套 tab 机制。

tab 打开后有三个页签：

| 页签 | 内容 |
|---|---|
| **更改** | 提交信息框 + 「暂存的更改 / 更改」两组文件列表；每行 hover 出 `+`（暂存）、`−`（取消暂存）、`↺`（放弃更改）/`✕`（删除未跟踪文件）；点文件名就地展开 unified diff（绿加红删、双行号、hunk 头） |
| **历史** | 分页加载的提交列表（**多泳道拓扑图** + 短 hash、作者、时间、分支/标签），点开看提交详情与该次提交的文件，再点文件看那次 diff |
| **分支** | 本地/远程分支列表、当前分支高亮、切换、**合并**、新建（**可选起点分支**）、删除；顶部按钮做 fetch / pull / push，没有上游时给「发布分支」 |

顶部还常驻：当前分支（点它跳到分支页）、ahead/behind 计数、刷新。
提交框支持 `Ctrl+Enter`（macOS `Cmd+Enter`）；工作区有改动时可以「贮藏更改」。

工作目录不是 Git 仓库时，面板给出路径输入框与「初始化仓库」，不会一片空白。

### 贮藏

有贮藏时，「更改」（未暂存）区块里出现贮藏区：一个下拉框列出全部贮藏（`stash@{n}` + 说明文字），
以及三个按钮：

| 按钮 | git 命令 | 效果 |
|---|---|---|
| **应用贮藏（保留）** | `stash apply <ref>` | 内容合并进工作区，**该条贮藏保留** |
| 恢复并删除 | `stash pop <ref>` | 内容合并进工作区，并从贮藏列表删掉 |
| `✕` 删除 | `stash drop <ref>` | 只删除，不动工作区 |

两个刻意的设计：

- **下拉框默认不选中任何一条**，未选时三个按钮都是禁用的。恢复/删除会改工作区或丢数据，
  给个默认值就意味着「点一下就动了 `stash@{0}`，而用户以为自己选的是别的」——
  宁可多一次显式选择。
- **「应用」与「恢复」是两个独立按钮**，不是两个选项共用一个入口。
  `apply` 不动贮藏列表、可以反复执行，所以它排在前面并做主按钮；
 想「取出来看看、但先别丢」的时候不必担心贮藏消失。
  三个操作都会先弹确认，确认语里带上 ref 与说明文字，让人看清动的是哪一条。
- **贮藏区放在「更改」区块里**（不是提交框下面）：应用贮藏产出的正是未暂存的改动，
  控件和它会影响的那份列表放在一起更直观。也因此这个区块不能挂在
  `unstaged.length > 0` 上——**工作区干净时恰恰最需要它**（先把贮藏取出来才有东西可看）。
- **应用撞上冲突时会如实说明**：`git stash apply` 冲突的返回值是「退出码 1 +
  `stderr` 为空 + `CONFLICT` 写在 `stdout`」，而带冲突标记的内容其实**已经落进工作区**。
  只读 `stderr` 就会得出结论「操作没有返回信息」，用户看到报错、文件却真的变了。
  现在失败后会立刻重拉一次真实状态，看到 `conflicted` 文件就把话说准
  （「{n} 个文件需要手动解决，内容已经写进工作区」），并在列表里把它们标成 `!`。

### 丢弃更改

「更改」分组的标题栏上有两个按钮：`+` 全部暂存，`⌫` 全部丢弃（都需要先确认）。
单个文件的丢弃按钮按文件类型分两种语义：

| 文件 | 按钮 | 实际动作 |
|---|---|---|
| 已跟踪（改动/删除/重命名） | `↺` 放弃更改 | `git checkout -- <file>`，还原到上次提交的内容 |
| 未跟踪（新文件） | `✕` 删除文件 | `git clean -f -- <file>`，**把文件从磁盘上删掉** |

之所以要分开，是因为 git 里未跟踪文件**没有任何备份**可还原。早先两种情况都发
`checkout --`，点未跟踪文件必然报 `error: pathspec ... did not match any file(s)
known to git`——这正是「丢弃未跟踪文件报错」的原因。现在未跟踪走 `clean -f`：
这是它唯一有意义的「丢弃」，按钮图标与确认语（「删除未跟踪的文件…会从磁盘上移除」）
也一并改成删除语义，避免用户以为是可逆的还原。

「全部丢弃」等价于「全部暂存」的反操作，按 **重置索引 → 删未跟踪 → 还原已跟踪**
三步执行，顺序不能换：新增并已暂存的文件要先经 `reset` 变回未跟踪，才会被 `clean`
正确删掉。它**不带 `-x`**，被 `.gitignore` 忽略的文件（构建产物、`node_modules`）
会保留——丢弃操作里误删这些代价最大，宁可少删。

### 从指定起点建分支

「+ 新建分支」展开后有**起点分支**下拉，同时列出本地分支与远程分支
（如 `origin/main`），默认是「当前 HEAD」。从远程分支建时显式加 `--no-track`——
`git checkout -b` 默认会把上游设成那个远程分支，但用户在下拉里选它通常只是想要
「以它为起点」，不该顺带绑定上游。

分支名里的空格会**边输入边换成中划线**，连续空白折叠成一个 `-`
（`feat my branch` → `feat-my-branch`）。git 本身不接受含空格的分支名，
与其等 `checkout -b` 报错再让用户回来改，不如把输入框直接变成最终值。
只动空白与中划线：`/`（`feature/x` 这类分层名）、`_`、`.`、中文都原样保留，
其余非法字符交给 git 报错——静默改写用户起的名字比报错更糟。

### 合并

分支页每行（非当前分支）有 `⇥` 合并按钮，把该分支合并进当前分支，支持两种策略：

- **允许快进**（默认）：能快进就快进，历史保持线性
- **强制合并提交**：等价 `--no-ff`，始终生成一个 merge commit

策略开关在分支页右上，做成显式切换而不是隐藏选项，因为团队对「要不要保留合并记录」
的要求差别很大。

冲突时合并会**如实失败**（不假装成功）：面板顶部出现「合并进行中」提示，
冲突文件在列表里标为 `!`，解决后正常暂存提交即可；也可以点「放弃合并」回到干净状态。

### 历史页的泳道图

每个提交左边的圆点不再是孤立的装饰，而是**真实拓扑**：分支分出去的提交落在右侧泳道，
用竖线和「分叉/汇流」横线连起来，一眼能看出哪些提交属于哪条线、在哪里合并回来。

- **当前分支是主角**：HEAD 所在那一行的节点放大、实心、用品牌色，分支名标签也高亮；
  第一个父提交那条主线用品牌色，其余泳道是中性色。
- 图由 Client 半自己算（`buildGraph`），不用 `git log --graph` 的字符画——
  那个是 ASCII 艺术，做不出圆点 + 竖线的样式，也不好和分页配合。
  算法前提是 `git log` 的输出顺序（新→旧），此时「谁的父提交是谁」可以一次前向扫描定下来：
  维护一组泳道格子记录「这条线在等哪个 commit」，当前提交占哪个格子就是它的泳道，
  处理完把格子改指向它的父提交（第一个父留原列 = 主线延续，其余父插新列 = 分叉），
  已经在等的父提交则并过去，避免为一个提交铺两条线。
- **分页会让图在页尾断开**：这一页里父提交还没加载时，列表尾会出现一行提示说明图被截断
  （「点加载更多接上」）。宁可显式说明，也不让人误以为历史就长这样。
- 泳道最多 6 列，再多也看不清；超出的一律并到最后一列并同样打出截断提示。

## 原理

一如既往是「Host 半 + Client 半」：

**Host 半（`index.js`）** 用 `execFile('git', [...])` 直接调 git CLI——不引入任何
git 库，也不开 shell，所以分支名/路径里的空格与引号不需要转义，也不存在命令拼接注入。
它把操作包成几条同源路由：

| 路由 | 用途 |
|---|---|
| `GET /git/status` | 仓库概要、暂存区/工作区变更、分支与远程状态、贮藏列表 |
| `GET /git/diff` | 单个文件的 unified diff（`staged=true` 看暂存区，`commit=<hash>` 看某次提交） |
| `GET /git/log` | 提交历史（`limit` / `skip` / `branch` / `file`）；每条带 `parents`，供界面画泳道图 |
| `GET /git/commit` | 单次提交的详情与改动文件 |
| `GET /git/branches` | 本地与远程分支 |
| `POST /git/action` | 所有写操作，按 `action` 分派 |

几条能说明取舍的细节：

- **`-c core.quotepath=false`**：git 默认把非 ASCII 路径转义成八进制，中文文件名会变成
  `\344\270\255` 这样的乱码。这是纯显示问题，但足够让人以为插件坏了。
- **porcelain 用 `-z`**：NUL 分隔是唯一无歧义的状态格式，重命名的原路径也靠它配对。
- **路径闸门**：`resolveRepo` 只接受绝对路径、要求目录真实存在，再 realpath 消掉符号链接；
  可用配置里的 `roots` 限定到若干根目录。这是唯一的路径入口。
- **未跟踪文件也能看 diff**：git 没有可比较对象，用 `--no-index` 对着空文件生成新增差异，
  读起来和 VS Code 一致。
- **丢弃按文件类型分流**：已跟踪走 `checkout --`，未跟踪走 `clean -f`。
  `checkout` 对未跟踪文件必然报 pathspec 错误，而 `clean` 又还原不了已跟踪的改动，
  一次丢弃里两种文件同时存在时两条命令都要跑，结果再合并成一份返回值。
- **写操作后回报最新状态**：省一次往返，也顺手消灭「提交完列表没变」这类错觉。
- **超时与截断**：普通命令 20s、写操作 120s（`stash apply/pop` 要写回一堆文件，
  大仓库叠上杀毒扫描时 20s 很容易不够，而超时被杀时 git 可能**已经把改动落盘了**，
  返回值却是空的 `stderr`）、网络命令 120s；diff 超过 40 万字符截断并标记，
  避免一个巨型 diff 把页面卡死。

**Client 半（`client.js`）** 只 `require('react')`，通过 `ctx.sidebarRightTabs.register`
注册 tab 类型（`kind: 'git'`），再用 `slots` 把主体与标题挂到
`sidebar.right.pane.tab` / `sidebar.right.pane.tab.title` 上。样式全部走宿主主题 token
（`--dsw-alias-*`），没有硬编码颜色，所以跟随明暗主题。

仓库路径来自**会话的工作目录**，取法和官方「文件」面板一致：

```js
const cwd = useSessions((sessions) => sessions.byId[sessionId]?.cwd)
```

`sessionId` / `useSessions` / `useTabInfo` / `t` 都由宿主按标准 props 注入，
**不存在 `props.view` 这种东西**——这里踩过坑：早先自造了一个 `props.view.cwd`，
于是路径永远是空的，面板一律显示「当前目录不是 Git 仓库」，而服务端一切正常。
`smoke.mjs` 现在按真实 props 契约渲染，并断言「会话 cwd 真的被当成仓库路径发了出去」。

## 安装

profile 的 `package.json`：

```json
{
  "dsh": { "profile": { "bundles": ["@local/dsh-git"] } },
  "dependencies": { "@local/dsh-git": "link:<本仓库路径>/dsh-git" }
}
```

在 profile 目录跑 `pnpm install`（`link:` 会自己建好 `node_modules/@local/dsh-git`）。
改 `dependencies`/`bundles` **必须重启 DSH** 才生效；纯 patch 行改动是即时的。
Client 半在重启后刷新一次页面即可看到。

## 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `roots` | `[]` | 允许操作的根目录数组。为空表示不限制（仍要求是真实存在的目录且在 git 仓库里）。填了就只接受这些目录及其子目录。 |
| `gitPath` | `"git"` | git 可执行文件。PATH 里没有 git 时指向绝对路径。 |

```yaml
- id: git
  name: '@local/dsh-git'
  config:
    roots:
      - 'D:\code'
```

## 验证

```powershell
node dsh-git\smoke.mjs   # 通过时打印 ALL PASS
```

冒烟测试两半都跑：Host 侧验证解析器（porcelain `-z`、log 字段流）、路径闸门，
并真的对一个**临时 git 仓库**做完整流程（暂存 → 提交 → 改文件 → 看 diff →
新建分支 → 放弃修改 → 丢弃/删除 → 贮藏）；Client 侧在 Node 里用极简 React + 极简 DOM
真跑注册契约、渲染与**焦点兜底**，断言中英文字典键一致、CSS 里没有硬编码颜色、只依赖 `react`。

### 焦点必须自己兜住（改这个插件时务必留意）

写操作会把 `busy` 置 true，面板内 21 个按钮随之 `disabled`。浏览器会立刻 blur
掉那个正持有焦点的按钮，焦点落到 `body`；而宿主的焦点恢复逻辑
（`dsh-client-ui-sidebar-right` 的 `observeSidebarFocus`）在这种情况下救不了场：

- 它的 `MutationObserver` 只看 `childList`，而 `disabled` 只是改属性、元素并未移除；
- `focusout` 里 `relatedTarget === null` 且元素 `isConnected` 时，它**直接清掉自己记录
  的焦点并断开观察**（`if (event.relatedTarget === null && focused?.element.isConnected)`）。

于是宿主再无任何可恢复的目标，焦点永久停在 `body`：表现为「操作完打字进不了输入框，
点别处也恢复不了」。同理，任何被 `setState` **卸载**的控件（新建分支表单、贮藏下拉框、
「贮藏更改」按钮）也会制造同样的问题。

因此 `client.js` 里有两条互补的兜底，改动相关代码时不要删：

| 函数 | 覆盖场景 | 时机 |
|---|---|---|
| `captureFocus` / `restoreFocus` | 按钮被 `disabled`、原生确认框把焦点交给系统 | `run()` / `refresh()` 里，`setBusy(true)` 与**弹确认框之前** |
| `releaseFocus(rootRef)` | 控件被卸载 | `setState` 卸载控件**之前** |

`captureFocus` 必须在 `setBusy(true)` 之前调用——一旦 `busy` 生效，浏览器已经把焦点
blur 掉了，那时再读 `document.activeElement` 就晚了。

**确认框同样要排在这一步之后**：原生 `window.confirm` 会把焦点交给系统（Chromium 里
`document.activeElement` 直接掉到 `body`），所以凡是要确认的动作，确认框都由 `run()` 统一弹
（`{ confirm: '问句' }`），而不是在点击回调里自己弹——那样 `captureFocus()` 只会读到 `body`，
「动之前焦点在面板里」永远为假，焦点再也还不回来。这正是「应用贮藏（保留）之后
输入框打不了字」的根因。

**还焦点的目标按三级退让**（`restoreFocus`）：① 面板外原来那个元素 → ② 动作前持有焦点的
面板内控件 → ③ 面板容器。第①级是「操作完回不到会话输入框」的解药：

- 用户在输入框里打字，鼠标移到面板点一个动作按钮，做完动作**应该能接着打字**，
  而不是把焦点留在面板里（留在面板容器上更是看不见焦点在哪）。
- 「原本在哪个输入框里」只能在**指针按下**那一刻读（`onPointerDownCapture`）：把焦点交给
  被点的按钮是 mousedown 的默认行为，排在 pointerdown 之后，等到点击回调里读已经是面板里的
  按钮了。所以根容器上挂了 `onPointerDownCapture: rememberOutsideFocus`。
- 按下时焦点本来就在面板里 ⇒ 记 `null`，不记「上一个面板外的元素」：用户在面板里连点几下时，
  把焦点甩回输入框才是打扰，这时按第②③级就近还给面板内的控件。
- 第③级（面板容器）是兜底，只为不让焦点掉到 `body` —— 宿主一旦看到焦点掉到 `body`
  就再也恢复不了。

`restoreFocus` 只在焦点「归我们管」时才动手：焦点已经落空（`body` / 无），或正停在动作前
那个控件上（那是点击带过去的）。用户自己把焦点放到别处（点了会话输入框、点了别的面板）
时绝不抢。它连试两次（`microtask` + `setTimeout 0`）：第一次很可能赶在 React 提交之前，
那一刻被点过的按钮还带着 `disabled`、浏览器拒绝聚焦，所以要等这一帧过去再来一次。

`smoke.mjs` 为此内置了一个极简 DOM（`makeDom`），把「焦点不能停在 body」「丢弃/贮藏做完
焦点回到会话输入框」「按下时焦点已在面板里就不甩出去」「确认框弹完之后焦点也要还回面板」
「控件被卸载时退到容器」「用户点到面板外时不抢焦点」都写成了断言，并用变异测试验证过它们
真的会失败。

`DSH_SMOKE_DEBUG=1` 会打印渲染出的 HTML 摘要。

## 已知限制

- 历史页的画布是**扁平泳道图**（每行一个提交 + 分叉/汇流连线），不是完整的多分支拓扑图：
  同时活跃的分支超过 6 条时会并到最后一列并提示截断。
- 冲突文件只标记、不提供三方合并编辑；请在编辑器里解决后回来暂存。
- 不支持交互式 rebase、cherry-pick、submodule 等进阶操作。
- 网络操作（fetch/pull/push）不弹凭据输入框，`GIT_TERMINAL_PROMPT=0`，
  需要凭据时会直接失败并在面板上显示 git 的报错。
